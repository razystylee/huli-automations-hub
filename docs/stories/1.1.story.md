## 📖 Story Description

**As a** Huli team member
**I want to** see a centralized dashboard that monitors and controls all our daily automation scripts
**So that** I can easily track job execution, view logs, and manually trigger jobs when needed without depending on external tools (OpenClaw)

**Context:**
Currently, we run 4 Python scripts daily via OpenClaw:
- Facebook Ads extraction (6:00 AM)
- Hotmart sales extraction (6:15 AM)
- Data consolidation (6:45 AM)
- Weekly funnel analysis (Wednesday 7:00 AM)

This story builds a **Mission Control dashboard** with built-in APScheduler to replace OpenClaw dependency.

---

## ✅ Acceptance Criteria

```gherkin
GIVEN I access the Mission Control dashboard at localhost:8000
WHEN the page loads
THEN I should see:
  - List of 4 Cron Jobs with their names
  - Próxima execução (next run time) for each job
  - Última execução (last execution time/status)
  - Result of last run (✅ SUCCESS or ❌ ERROR)
  - "Execute Now" button for each job

WHEN I click "Execute Now" on any job
THEN the job should:
  - Start executing the Python script
  - Show status as RUNNING
  - Capture stdout/stderr
  - Log results to JSON file
  - Update dashboard with result

WHEN the page is idle
THEN:
  - Dashboard auto-refreshes every 30 seconds
  - Shows updated job status
  - No manual page refresh needed

WHEN I click on a job to view logs
THEN:
  - I should see last 10 executions
  - Each log shows: timestamp, status, duration, output
  - Errors are clearly visible

WHEN viewing the /health endpoint
THEN:
  - API returns status: ok
  - Scheduler status: running
  - Number of scheduled jobs: 4
```

## 🎯 Scope

### IN SCOPE

```
✅ FastAPI backend with APScheduler
  - GET /api/jobs (list all jobs)
  - GET /api/jobs/{id}/logs (view logs for a job)
  - POST /api/jobs/{id}/execute (manually trigger job)
  - GET /health (health check)

✅ Job Scheduler
  - 6:00 AM: facebook_ads_to_sheets.py
  - 6:15 AM: hotmart_to_sheets.py
  - 6:45 AM: huli_consolidator.py
  - Wednesday 7:00 AM: analisar_funis.py

✅ Execution Engine
  - Subprocess execution of Python scripts
  - stdout/stderr capture
  - Execution time tracking
  - Error handling (job errors don't stop scheduler)

✅ Logging System
  - JSON structured logs
  - One log file per job
  - Last 100 executions per job
  - Status: SUCCESS, ERROR, RUNNING
  - Precise timestamps (with timezone)

✅ Dashboard UI
  - HTML/CSS/vanilla JS (no frameworks)
  - Job list with status indicators
  - Manual trigger buttons
  - Log viewer (last 10 executions)
  - Auto-refresh every 30s
  - Mobile responsive

✅ Configuration
  - jobs_config.json for job definitions
  - .env for credentials (Hotmart, Facebook, Google)
  - Python 3.8+ support
  - America/Sao_Paulo timezone
```

### OUT OF SCOPE

```
❌ Database (use JSON files for MVP)
❌ Authentication/Login
❌ Notifications (Telegram, Email, Slack)
❌ Persistent history (>100 executions per job)
❌ OpenClaw integration
❌ Docker/containers
❌ Agentes de IA
❌ Kanban tasks
❌ Advanced analytics
❌ Multi-user support
```

## 🚨 Risks & Mitigation

| Risk | Impact | Probability | Mitigation |
|------|--------|-------------|-----------|
| **Scheduler clock drift** (time skew) | High | Low | Use `timezone('America/Sao_Paulo')` in APScheduler; Monitor with health check |
| **Script crashes** (missing .env, API errors) | High | Medium | Try/catch wrapper in execution_service; Log full stack trace; Don't block scheduler |
| **Credentials exposure** (.env in git) | Critical | Medium | Add .env to .gitignore; Use .env.example template; Document setup clearly |
| **Log file growth** (>100 entries) | Medium | Low | Implement log rotation (keep last 100 entries); Clean old logs periodically |
| **Missing scripts** (at deploy time) | High | Low | Copy scripts to jobs/ directory before testing; Document prerequisite |
| **Timezone issues** (DST, UTC mismatch) | Medium | Medium | Hardcode America/Sao_Paulo; Store all timestamps with timezone info |
| **Job overlap** (one job slow, next starts) | Medium | Low | APScheduler prevents overlap by default; Monitor execution times |
| **Long-running scripts** (>timeout) | Medium | Low | Set timeout per job in config; Log timeout errors; Alert user |
| **Dashboard not updating** (stale data) | Low | Low | 30s auto-refresh; Add "Last Updated" timestamp; Health check |
| **Initial setup complexity** | Low | Medium | Clear README; Setup script; .env.example with all required vars |
