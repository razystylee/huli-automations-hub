# Story HUB-2.1: Hotmart Sales Daily Extraction → Google Sheets

**Status:** Draft

**Timeline:** 4-6 hours development

---

## 📖 Story Description

**As a** Huli analytics team member
**I want to** automatically extract daily sales data from Hotmart and consolidate them in Google Sheets
**So that** I can track sales performance, analyze pricing strategies, and maintain a complete historical record without manual data entry

**Context:**
Daily sales extraction from Hotmart was previously done via `gog` CLI tool. This feature rebuilds it using Google Sheets API Python library for better reliability in serverless environments (Railway). The system should extract sales from the previous day (D-1) every morning and append them to the centralized "Todas as vendas Tio Huli" Google Sheet.

## 📝 Implementation Notes

### Technical Decisions
1. **Google Sheets API (Python)** instead of `gog` CLI
   - Better for serverless/Railway environment
   - Easier error handling and debugging
   - Uses same pattern as Facebook Ads extraction
   - Requires GOOGLE_CREDENTIALS_JSON and GOOGLE_REFRESH_TOKEN

2. **Daily batch processing** instead of real-time
   - Sufficient for analytics use case
   - Reduces API calls and cost
   - Easier to schedule and monitor

3. **Local CSV backup** for audit trail
   - Quick local recovery if needed
   - Useful for debugging data issues
   - Stored in `/tmp/` on Railway (ephemeral)

### Known Risks & Mitigations
- **Risk:** Hotmart API rate limits
  - **Mitigation:** Implement retry logic with exponential backoff
  - **Mitigation:** Schedule outside peak hours (7 AM is safe)

- **Risk:** Google Sheets quota exceeded
  - **Mitigation:** Batch append (multiple rows in one request)
  - **Mitigation:** Monitor sheet size and archive old data quarterly

- **Risk:** Missing credentials in Railway
  - **Mitigation:** Script prints clear error message listing missing vars
  - **Mitigation:** Validation on startup before API calls
